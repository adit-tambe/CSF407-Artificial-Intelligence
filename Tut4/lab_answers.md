## Task 0: STRIPS Formulation & Action Primitives

### Initial State Configuration
The world begins with ground atoms describing the starting positions of the entities:
$$S_0 = \{\text{At}(\text{Robot}, A), \text{At}(\text{Package}, A)\}$$
Both the mobile robot and the deliverable package reside at location $A$. Under the Closed World Assumption, all unstated fluents (e.g., $\text{Holding}(\text{Package})$, $\text{At}(\text{Robot}, B)$) are assumed false.

### Goal Condition
The terminal condition specifies that the package must reside at destination node $C$:
$$G = \{\text{At}(\text{Package}, C)\}$$
Any final state $S_f$ where $G \subseteq S_f$ is recognized as an acceptable solution. The robot's final location is unconstrained.

### Domain Action Inventory
The agent possesses three parameterized action schemata:
1. **$\text{Move}(from, to)$:** Transports the robot between adjacent nodes.
   * *Preconditions:* $\{\text{At}(\text{Robot}, from)\}$
   * *Delete List:* $\{\text{At}(\text{Robot}, from)\}$
   * *Add List:* $\{\text{At}(\text{Robot}, to)\}$
2. **$\text{PickUp}(pkg, loc)$:** Loads a package at the current location.
   * *Preconditions:* $\{\text{At}(\text{Robot}, loc), \text{At}(pkg, loc)\}$
   * *Delete List:* $\{\text{At}(pkg, loc)\}$
   * *Add List:* $\{\text{Holding}(pkg)\}$
3. **$\text{Drop}(pkg, loc)$:** Unloads a carried package at the current location.
   * *Preconditions:* $\{\text{At}(\text{Robot}, loc), \text{Holding}(pkg)\}$
   * *Delete List:* $\{\text{Holding}(pkg)\}$
   * *Add List:* $\{\text{At}(pkg, loc)\}$

### Initial Action Applicability
In state $S_0$:
* **$\text{PickUp}(\text{Package}, A)$** is immediately applicable because both $\text{At}(\text{Robot}, A)$ and $\text{At}(\text{Package}, A)$ hold.
* **$\text{Drop}(\text{Package}, C)$** is illegal because its preconditions require $\text{At}(\text{Robot}, C)$ and $\text{Holding}(\text{Package})$, neither of which holds in $S_0$.

## Task 1: Valid Plan Synthesis & State Trajectory

The optimal plan generated by the BFS progression planner consists of 4 steps:

1. $\text{PickUp}(\text{Package}, A)$
2. $\text{Move}(A, B)$
3. $\text{Move}(B, C)$
4. $\text{Drop}(\text{Package}, C)$

### State Progression Trace
* **$S_0$:** $\{\text{At}(\text{Package}, A), \text{At}(\text{Robot}, A)\}$
* **$S_1$ (after PickUp at A):** $\{\text{At}(\text{Robot}, A), \text{Holding}(\text{Package})\}$
* **$S_2$ (after Move A $\to$ B):** $\{\text{At}(\text{Robot}, B), \text{Holding}(\text{Package})\}$
* **$S_3$ (after Move B $\to$ C):** $\{\text{At}(\text{Robot}, C), \text{Holding}(\text{Package})\}$
* **$S_4$ (after Drop at C):** $\{\text{At}(\text{Package}, C), \text{At}(\text{Robot}, C)\}$

Because $G = \{\text{At}(\text{Package}, C)\} \subseteq S_4$, the plan successfully terminates.

## Task 4: The Progression Planning Cycle

The planner interleaves logical deduction and state-space graph search:

```text
               Current World State (S)
                          │
                          ▼
             Candidate Action Set (A)
                          │
                          ▼
            Precondition Check: S |= Pre(a)?
               ├── Yes ──► Apply Add/Delete Lists ──► Successor State S'
               └── No  ──► Prune Invalid Action
                                                       │
                                                       ▼
                                            Goal Test: G subset S'?
                                               ├── Yes ──► Extract Plan
                                               └── No  ──► Enqueue in BFS
```

* **Deductive Logic:** Restricts transitions strictly to legal, physically sound actions.
* **Search Engine (BFS):** Navigates the combinatorics of successor states to guarantee finding the shortest action sequence.

Tracking state mutations verifies the semantic fidelity of the planning system:

## Analytical Reflections

### 1. Purpose of Preconditions and Effects
Preconditions enforce causal boundaries, guaranteeing that actions are only executed when environmental conditions permit. Effects formally specify state mutations (add and delete sets), ensuring the frame problem is resolved deterministically without implicit side effects.

### 2. Failure Modes Without Precondition Validation
Omitting preconditions leads to physically impossible or hallucinated actions (e.g., dropping a package that was never picked up, or moving across disconnected warehouse nodes).

### 3. Plausible vs. Valid Plans
A sequence of plausible actions (e.g., "Pick up package, drop package at C") is not a valid plan unless every intermediate precondition is satisfied at the specific temporal instant the action is invoked.

### 4. Essential Plan Verification Criteria
A plan validator must check:
* Ground applicability: $S_{t-1} \models \text{Pre}(a_t)$ for all $t=1 \dots T$.
* Transition correctness: $S_t = (S_{t-1} \setminus \text{Del}(a_t)) \cup \text{Add}(a_t)$.
* Goal satisfaction: $G \subseteq S_T$.

### 5. Role of Deductive Reasoning
Deductive logic acts as a guard on graph edges. An edge exists between node $S$ and node $S'$ under action $a$ if and only if $S \models \text{Pre}(a)$ and $S' = \text{Result}(S, a)$.

### 6. Planning as Graph Search
By defining ground states as vertices and valid action applications as directed edges, classical planning transforms into graph traversal. Uninformed BFS guarantees finding the minimum-length plan when action costs are uniform.
